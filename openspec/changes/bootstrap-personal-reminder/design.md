## Context

当前仓库已有可构建的 Swift 菜单栏应用、SQLite 事项账本和 DeepSeek 单提醒解析器，但仍处于未完整验收的 V1 实现中。参见 `proposal.md` 与 `docs/design/personal-reminder-v1.md`。目标平台为 macOS，本机单用户；模型首个验收目标是 DeepSeek。窗口应即开即走，所有提醒决定与状态需要在重开应用后恢复。

## Goals / Non-Goals

**Goals:** 用短路径完成录入；原话优先落盘；让模型理解与定时通知解耦；提醒结果可回看、可恢复；每个跨时钟的状态变化可独立验证。

**Non-Goals:** 引入 Pi 编码 Agent/工具和会话作为待办数据库；云端同步；应用退出后的后台服务保证；完整待办项目管理；在纯文档阶段创建空的应用模块或假通过的测试。

## Decisions

1. **原生 Mac 客户端作为实现方向。** 建议 SwiftUI 承载设置、列表和轻量管理窗口，必要处以 AppKit 实现菜单栏、全局快捷键、跨显示器浮层；系统通知采用 macOS API。比 Electron/内嵌 Pi 运行时更贴合单机轻量与原生通知目标。实际采用前验证目标 macOS 版本、热键注册、全屏浮层与通知点击跳转的可行性；这些不改变行为规格。
2. **单一本地事项账本与显式提醒周期。** 以本机持久化记录原话、可修改内容、短标题、完成/取消状态、识别状态、首次与下次提醒、真实截止/建议完成及来源、每轮已实际通知次数、下一个计划时间、手动修改版本。推荐 SQLite 保证原话保存、模型结果提交、主动推迟和通知轮次更新的原子性；不可把系统通知当唯一状态源。把“事项是否完成”与“识别是否完成”“提醒是否已回应”分开，避免待识别等同取消或已完成。单项提醒派发需要稳定标识以去重；应用重开对当前到期项只生成一个聚合补发，不重放过去轮次。
3. **写入优先的异步 AI 管线。** 回车后先写原话并关闭浮层，异步请求模型返回单事项受约束结构；识别中仅由菜单栏显示状态，不弹出无最终提醒时间的反馈卡，成功后只弹一次最终结果卡。参考 V11 提示词的逐行动语义推理，但输出只包含一项可安排行动或“需分录”：两个各需提醒的独立行动必须保留原话、提示分两次录入，不自动拆分也不只安排后者。请求带原话、当前日期/时区与本次事项必要上下文；应用程序只做 JSON 字段/枚举、日期、过去时间、明确截止先后、证据引用等通用校验，移除原有明天/后天等语义正则；对可描述的输出错误最多纠错一次。手动修改为相关字段设版本边界，提交迟到结果前再次比较版本/事项状态。失败或需分录均保留为待识别，前者可重试/手动设时，后者突出“分两次录入”及撤销原句入口；统一安排一次 15 分钟后的“尚未安排”提示以防原话遗忘；失败通知与菜单栏持久标记均提供入口。超时为有界值，服务故障不执行模型纠错重试。没有凭据时以连接测试作为录入门槛，已录入的事项不会因网络中断丢失。
4. **定时以持久化下次行动为真源。** 每次启动、唤醒、事项更新和时钟变化时重算到期行动；通知是否实际发出应有记录，勿扰/系统折叠下无法推断用户是否看见。首次提醒后只有真实派发才推进未回应计数；主动推迟创建新轮次。到期集合批量组装为一条通知，保存关联事项标识供点击直达。每日汇总在本地时区每天按配置时分执行且独立于单项提醒；同一轮时间冲突应以一条可识别通知处理，不重复轰炸。调度目标是尽力准时，不承诺退出应用时精准触达。
5. **模型接口边界按任务而不是 Agent 会话设计。** 提供独立的“结构化解析一条事项”和“仅解析当前事项提醒/明确截止时间修改”，首版对 DeepSeek 验收，设置可改地址/模型/Token；不开放 shell、文件系统或自动执行用户事项的工具。Token 明文在应用专属本地配置文件（建议权限 0600；目录仅用户访问），页面只显示掩码，日志错误信息脱敏；本机已有权限的程序仍可能读取该文件，是用户明确接受的安全取舍。历史原话不批量发给模型。
6. **快捷路径与纠错路径分离。** 输入浮层只新增；通知只引导进入当前事项/通知集合；管理界面提供手动标题/内容编辑、提醒预设/日期选择与仅限时间的自然语言解析。提醒面板中的自然语言只解析下一次提醒；编辑窗的自然语言只解析提醒与明确截止，按字段预览、确认后一起提交，夹带内容修改要求必须拒绝而非忽略。模型不编辑标题或内容；内容手动编辑不触发识别。原话明确截止优先于模型建议，越过真实截止必须确认；用户手动选定时间始终胜过迟到的建议。

## Risks / Trade-offs

- [系统通知权限、勿扰及通知折叠无法确保用户已看见] → 菜单栏持久状态、补发聚合、权限引导，不以“看见”为重试依据。
- [模型语义正确但日期解释错误，结构校验难发现] → 保存结果短反馈展示实际时间与出处，允许快速改时；不可声称自动识别百分百正确。
- [明文配置泄露 Token] → 用户专属目录与文件权限、掩码、日志脱敏；如风险不可接受，后续改钥匙串需另立变更。
- [应用退出、睡眠、时区/系统时间变化] → 启动/唤醒/时钟变化重算，补发一条，不回放历史通知；macOS 行为需真机验收。
- [提醒频繁或模型调用延迟] → 有界重试及超时，用户可反复推迟；试用两周评估录入速度、漏提醒和打扰程度。

## Migration Plan

已有用户本地事项必须保留原来的状态与提醒时间；此变更仅对新录入使用新模型输出，不自动重新解释旧事项。先实现本地存储、配置与通知权限检查，再打通输入/解析和提醒/处理；用模拟时钟及假模型覆盖边界后在 Mac 真机验证权限和睡眠恢复。尚未完成任务和验收时保留 change 为活跃状态，不归档；如原生集成验证失败，调整实现设计但保持能力规格不变。
